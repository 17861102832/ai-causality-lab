## 一、技术知识点（工具/平台/模型/功能/原理等）

## 三、踩坑与解决方案

1. **问题**：AI 写 Inno Setup（.iss）/NSIS 脚本老是写错。
   - **原因**：`[2025-09-12 12:08] zhaokang`——「.iss 语法 ai 学不会，一直写错」「上下文丢失。solo 模式下」。
   - **解法**：`[2025-09-12 12:09] 刘金良`——「语法不同，可以把语法文件给 ai」；`[12:07]` 换工具会好很多；`[12:09]` 月末试 max。
   - **结论**：脚本类任务受「agent + 模型」共同决定，可换工具/换模型/喂语法文件。

2. **问题**：用 TRAE 改前端样式成功率低。
   - **原因 / 现象**：`[2025-10-14 09:16] 王渤`——「这两天 trae 帮改样式总是成功率很低」「改完一片红」。
   - **归纳**：`[2025-10-14 09:17] 刘金良`——「trae 最头疼的一个是样式，一个是前端测试」。
   - **结论**：样式与前端测试是 TRAE 已知薄弱环节。

3. **问题**：SOLO 模式上下文容易丢失 / 流程控制不好。
   - **原因**：`[2025-09-12 12:08] zhaokang`「上下文丢失。solo 模式下」；`[2025-09-28 05:56] FYF`——「TRAE 的流程控制不好，上下文非常容易丢失」。
   - **解法 / 结论**：`[2025-09-28 05:56] FYF`——「不过你拿来当 api 用，性价比还是可以的」；`[2025-10-27 03:02] 刘金良`——「SOLO 最大的问题，是不支持 mcp」「接入自己的东西很麻烦」；`[2025-10-27 05:01] 刘金良`——「SOLO 写界面用用，后端还是用别的吧」。

4. **问题**：Android/游戏内集成本地 AI 成本不可控。
   - **现象**：`[2025-09-13 04:38] 刘文溢`——「接 AI 的成本有些不可控哦」；`[2025-09-13 12:43-12:45] 刘文溢/NICK`——「控单次的输出流量确实可以在一定程度上控成本，但是用户正常游戏的流量怎么控制？按对话次数进行收费？」「多重控制！！！优先付费客户」；引用 TRAE 的「600 次的超级请求和排队机制」作为样板。
   - **结论**：做 0-1 种子期产品时，需在成本与规模间取舍（`[2025-09-13 12:47] 刘文溢`：「我考虑的是 0-1 种子期，而不是 1-100 的成长期」）。

5. **问题**：Unity 版本升级踩坑。
   - **解法 / 结论**：`[2025-09-25 08:53] FYF`——「unity 版本升级全是坑，能不动就不要动」；`[08:51]` 维护老项目被要求切团结引擎很麻烦。

6. **问题**：iOS 端做热更新被苹果审核打回。
   - **原因**：`[2025-09-25 08:59-09:05] FYF`——「不是技术上不行，是苹果审核不让」；「我把 lua 所有的函数全改了名字，脚本二进制混淆，后面还是一样被警告，老老实实下架」；「苹果没有查不出来的，只在于他要不要查你了」「先给你电话，要求技术回复问题，然后他们会 review，有问题发警告信，不行就下架封号」。
   - **结论**：`[2025-09-25 09:06] FYF`——「只要被盯上，打了记号以后就很难了。所以，不要反复挑战苹果审核」；`[09:10]`——「我有好几个游戏审核打回了，老老实实关闭热更，走发版」。游戏类目审核相对宽松、有部分热更空间，但儿童品类严格。

7. **问题**：AI 生图缺乏常识，连环画内容出错。
   - **现象**：`[2025-10-21 09:00] 刘金良`——豆包生成连环画「看起来挺好，但是每张图都有问题：桃园三结义，三者还没有武器；温酒斩华雄得有曹操、袁绍；三英战吕布，连吕布都没有」。
   - **原因**：`[2025-10-21 09:04-09:05] 刘金良`——「AI 确实不理解什么豹头环眼」（张飞被画成豹子脸/豹子尾）。
   - **解法**：`[2025-10-21 09:27] FYF`——「你用混元试试，效果比豆包要好不少」；`[2025-10-21 09:47] FYF`——「豆包不行，你反馈了，他也改不了」；`[09:50] 用户155059`——炼 LoRA / 上传参考图稳定角色一致性。
   - **结论**：`[2025-10-21 09:39] 刘金良`——「AI 还是没文化」；可用于做「找茬/挑错」游戏（把缺陷变成玩法）。

8. **问题**：飞书项目被企业同事可见。
   - **现象**：`[2025-09-23 09:49] 王渤`——「用飞书项目创建的自己的项目，企业里的人都能看到」，所以放弃用飞书项目。
   - **替代**：`[2025-09-23 09:59] 丁知成`——「建个多维表格也行的。反正自己用」；个人飞书账号用不了飞书项目（`[09:58] 王渤`）。

9. **问题**：企业认证与个人认证选择。
   - **解法**：`[2025-09-26 04:53] 刘文溢`——「建议你还是去注册个企业吧，个人会很受限的」；`[2025-09-22 12:06]` 企业认证并不复杂；`[2025-09-23 09:42] 刘`——「有营业执照就行」。

```
- 输出《REQ_项目名称.md》：需求背景、目标、验收标准、非功能指标、排除项
- 任何需求描述必须满足 INVEST 原则；验收标准必须"可测试、可量化"
- 需求未对齐，禁止进入下一阶段

阶段2【Architect-架构】
- 输出《DESIGN_项目名称.md》：系统上下文图（C4）、接口契约、技术栈、目录结构、时序图
- 先画后写：所有图用 Mermaid 源码呈现；无图不编码
- 对外接口先行：REST/GRPC 字段、错误码、鉴权规则一次写全

阶段3【Atomize-原子化】
- 任务粒度 ≤ 20 行代码或 ≤ 1 个函数；单任务必须 0.5 d 内完成
- 输出《TASK_序号_名称.md》：任务目标、输入输出、验收脚本（pytest/main 可直接跑）
- 复杂流程必须继续拆，直到"傻子也能一次写对"

阶段4【Approve-审批】
- 人工逐条 checklist：①验收脚本能否跑通 ②是否引用了设计文档 ③是否有性能/安全 TODO
- 审批通过后，在任务头部写入 APPROVED@yyyy-mm-dd-HH:MM 并 commit
- 未通过审批，AI 禁止生成生产代码

阶段5【Automate-自动化】
- AI 按 TASK 顺序编码；先写单元测试（pytest），测试红→绿→重构节奏
- 代码提交信息格式：<task-id>: <desc> (test=<cov>%, lint=pass)
- 测试覆盖率 < 80 % 或 lint 报错，自动阻塞提交

阶段6【Assess-评估】
- 生成《FINAL_项目名称.md》：SonarQube 扫描得分、测试覆盖率、遗留 TODO、性能基准
- 若 Sonar 阻塞级 bug > 0 或覆盖率 < 80 %，强制回滚到 Atomize 阶段
- 评估通过后打 tag：v{版本}-6A{日期}
```

### user_rules.md ── 5S 敏捷规则（个人级）
```
# 5S-Agile-for-Trae
# 适用：个人侧规则，写进 Trae → Settings → Rules → User Rules
# 目标：让开发者成为"AI 驯兽师"，杜绝跳步与返工

1S - 文档（Document）
- "先写文档后写代码"是铁律；任何代码文件头部必须带 3 行注释：作者、创建/修改时间、对应 TASK-ID
- 目录说明 README 必须同步更新，否则 AI 拒绝继续编码

2S - 流程（Sequence）
- 严格执行"需求→设计→任务拆分→测试→代码"顺序；禁止反向跳转
- 每日启动 Trae 时，先输入"5S-check"，AI 自动校验昨日产出是否合规

3S - 问题（Solution）
- 遇到报错第一步：贴官方文档链接 + 错误日志；禁止直接问"为什么错了"
- 搜索引擎 / 官方 Doc 未读完，不允许让 AI 直接给答案

4S - 约束（Constraint）——三大"绝不允许"
  a. 绝不允许项目延期：提前 3 d 识别风险，延期必须同步更新甘特图 & 通知干系人
  b. 绝不允许超出范围：新增功能须先改《REQ》并评估影响，未经审批不加
  c. 绝不允许低级错误：编译报错、测试 fail、文档不一致，零容忍立即回滚

5S - 环境（Standardized-Env）
- 全团队统一：Win11 + Python3.11 + Node20；包管理锁文件（requirements-lock.txt / package-lock.json）强制提交
- IDE 插件版本锁定：Prettier@2.8.0、ruff@0.6；差异提交前自动 format，不通过禁止 push
- 输出规范：函数注释必须含参数类型、异常、返回值结构；示例见下
  def foo(bar: int) -> str:
      """
      :param bar: 整数，范围 0-100
      :return: 字符串，格式 "code#desc"
      :raises ValueError: 当 bar 不在范围内
      """
```

> 使用方式：打开 Trae → Settings → Rules；Project Rules 页签粘贴 6A-Workflow-for-Trae 全文；User Rules 页签粘贴 5S-Agile-for-Trae 全文；新建项目时在对话框输入激活口令 `6A-start` 即自动按 6A+5S 节奏推进。
