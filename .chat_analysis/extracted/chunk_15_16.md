### 1. Vibe coding 上线前安全清单（AI 造应用必备）
- [2026-06-26 14:55] 用户031695 转帖（X @PrajwalTomar_，作者有 20+ 年开发经验、在代理公司做过 60+ 应用）。原文 11 条要点：
  1. 保护自己而不只是应用：一旦收集用户数据就进入法律范畴（GDPR、CCPA），要有隐私政策、知道用户数据存在哪里。
  2. **Row Level Security（RLS）**：没有 RLS，任何人打开 DevTools 就能读你整个数据库。Supabase → Auth → Policies，"Zero policies means your app is naked"，5 分钟可修复。
  3. 测失败路径而非只测 happy path：错密码连点 5 次、重置不存在邮箱、验证链接点两次、用已存在邮箱注册，"Catches 80% of auth bugs"。
  4. 2 分钟安全基线：提示 AI "Review my app as a security specialist and make sure I have strong security headers and a solid baseline security posture."。
  5. OWASP 审查：提示 "Review my app against OWASP standards and highlight vulnerabilities."，SQL 注入、XSS、认证 bug 在这里被抓到。
  6. 客户端校验是 UX 不是安全：攻击者会关 JS 直接打 API，服务端每次都要再校验。
  7. AI 代码泄露数据的 3 个地方：前端里的 .env、返回过多的 API 响应、日志里的密钥。提示 "Check my app for credential or sensitive data leaks in frontend or API routes."。
  8. 前端放 API key 就是 game over：只要在浏览器里就假定已泄露，移到服务端或做代理。
  9. 给付费 API 端点加限流，否则账单被刷爆——"I've watched a Supabase bill jump from $20 to $200 in a day."
  10. 公开表单上 CAPTCHA（**Cloudflare Turnstile 免费**）+ CORS 锁域名，10 分钟挡掉机器人洪水。
  11. 不泄露信息的错误提示："User not found"，而不是 "SELECT * FROM users failed"，服务端记完整错误，给用户看通用信息。
- 结论金句："Build fast. Just don't ship naked."

### 4. Grok Build 默认上传整个 Git 仓库（重大隐私点）
- [2026-07-13 20:15]（用户031695 转发消息）：⚠️ "Grok Build 默认会把整个 Git 仓库上传到他们的 GCP，包括完整 Git 历史，不只是 AI 实际读取的文件。更离谱的是，关闭 'Improve the model' 并不会阻止这类代码库上传。"
- 关闭方法一（配置文件）：Windows 路径 `C:\Users\你的用户名\.grok\config.toml`，macOS/Linux 路径 `~/.grok/config.toml`，加入：
  ```PLAIN_TEXT
  [harness]
  disable_codebase_upload = true
  ```
  PowerShell 可直接运行：
  ```PLAIN_TEXT
  $p = "$HOME\.grok\config.toml"
  New-Item -ItemType Directory -Force (Split-Path $p) | Out-Null
  Add-Content -Path $p -Value "`n[harness]`ndisable_codebase_upload = true"
  ```
  修改后彻底退出并重启 Grok Build。
- 关闭方法二（后续更正）[2026-07-13 20:34]：进入 Grok 后输入 `/privacy opt-out`。
- 讨论：[2026-07-14 02:11] 用户031695 "我给关了。他们说关了之前的数据都会删除"；AAG "逻辑删除也是删除"；用户031695 "只能说马斯克太阴了，没有舆论他们就会一直收集"。
