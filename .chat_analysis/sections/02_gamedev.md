# 第二部分：AI 辅助游戏开发实战

想用 AI 独立做出一款游戏，真正的门槛早已不在"写代码"，而卡在选题、引擎与 AI 的协作方式、架构与防作弊、工程纪律、测试验收、上线部署这六道"非代码"关卡上——本部分把「TRAE 交流群｜游戏」两年里群友踩过的真实坑与可复制的做法，按上手顺序系统整理出来。

---

## 2.1 选题与品类：哪些游戏适合 AI 做，瓶颈在哪

### 2.1.1 天然适合 AI 开发的品类

群里反复验证过一个规律：**规则越清晰、越依赖数值而越不依赖画面的品类，AI 越容易做成**。

- **塔防**：赵子博用 TRAE SOLO 独立开发六边形塔防时，选择从经典塔防入手，理由正是"规则清晰"（`[2025-09-12 19:24]` 赵子博）。
- **策略 / 模拟经营 / 数值向**：李剑明确说过适合的品类——
  > `[2025-11-03 17:48] 李剑`：「策略类啊，模拟经营类啊这种，主要玩数值的」，「只要不是太依赖画面的还凑合」。
- **挂机放置**：这是被玩家点名偏好的品类。李巍、吴晓斌都公开表示这类游戏"根本懒得自己玩/挂机想法赞同"（`[2026-09-30 14:41-14:42]` 吴晓斌 / 李巍），且有群友专门做挂机小游戏靠激励视频变现（见 2.7）。
- **轻量交互 / 影游原型**：赵子博对"AI 交互游戏引擎"的本质判断是——
  > `[2025-09-12 11:27] 赵子博`：「实际上就是个视频播放器+按钮」。
  适用场景为轻量交互式游戏、影游原型。FYF 进一步指出 AI 视频更适合影游、好处是"工作流解耦"，但"对于独立游戏来说，这个成本太高了"（`[2025-09-13 12:14]` FYF）。

**小游戏市场的实际出圈规律**：JasonShane 观察到趋势"还是休闲类为主……最容易出圈的是挂机、无脑、点点点"（`[2026-05-25 10:01]`）。

### 2.1.2 AI 游戏的三大瓶颈

群内对"AI 做游戏"最大的共识，是**资源（美术/音效/策划）而不是代码**才是真正的天花板。李巍给出过最完整的判断：

> `[2026-06-03 12:47] 李巍`：「AI 游戏最严重的问题在于资源的生成。无限剧情、无限分支、npc 的自由对话意味着无限的资源，包括建模、动画、特效、场景、音乐音效、表格配置等等，而 AI 只能提供无限的文本……如果让 AI 在游戏运行时动态生成资源，你只能得到简陋、粗糙和混乱的东西，这本质还是 AI 能力不足。」

对应地，群里把它拆成三块瓶颈：

| 瓶颈 | 具体表现 | 群内证据 |
|---|---|---|
| **美术产能** | "美工才是最后一道鸿沟" | `[2026-04-21 08:19] 吴晓斌`：「我直接就不搞了，发现美工才是最后一道鸿沟」；`[2026-04-09]` 又说"做游戏最大的痛点开启以后，反而代码现在是最简单的" |
| **AI 读图/生图弱** | 让 AI 画 UI、画地形失败 | `[2026-04-20 09:00~09:29] 李巍`：让 Godot/AI 画飞行棋棋盘都画不出来，"我图塞嘴里了它不会看"，最后改用"把 UI 元素的像素大小和坐标明确告诉 AI" |
| **玩法验证 / 自嗨** | 做完没人玩 | `[2026-06-15 08:19] 李巍`：「做游戏怎么避免自嗨啊？我发现做的游戏除了我自己没人喜欢玩」 |

此外还有一条"动态表现"短板，李剑点得很准：

> `[2026-03-03] 李剑`：「我现在就是用 webgl，开发效率是很快，可是画面表现力太差了……尤其是动态效果，动画啊特效啊都只能用序列帧，而序列帧又是 AI 生图最大的短板」。

### 2.1.3 "游戏"的界定与题材红线

选题前必须先搞清平台口径，否则做完上不了架：

- **什么是"游戏"（审核口径）**：`[2025-10-23 17:04] 李佳宁`——「游戏指要有成长或者数值体系的」。
- **互动空间作品不能写成"游戏"**：群里有一个典型踩坑——互动空间作品被拒两次，原因是作品"不属于『游戏』，建议不要使用『游戏』表述"。李巍一度误以为描述里不能出现"游戏"字样，实际是**作品内部不能出现"游戏"字样，不是描述不能有**（`[2026-04-19 09:00~10:22]` 李巍 / AI发明家）。

### 2.1.4 选题的现实主义：抄 80%、跑量

对独立开发者，群里给出的不是"憋大招"而是"快速试错"：

- `[2026-06-15 08:25] AI发明家`：「抄市面上的游戏，80% 抄，20% 创新」；`[2026-06-14 15:13] 李巍`：「玩法可以抄或者缝」。
- H5 跑量路线：`[2026-09-14 21:37] 用户427395`：「单干还是 h5 游戏比较好，出品快 轻量 拼创意」；用户031695 更直接——「跑量永远是答案」（`[2026-09-14 22:18]`）。
- 反面提醒：`[2026-05-31 16:39] JasonShane`观察到"越正经的高质量游戏越容易暴毙……反而很离谱很无聊的游戏很容易爆火"；李巍补充"很多高质量游戏只是画面精美，但不好玩"。

## 2.2 技术栈与引擎选型

### 2.2.1 主流引擎/技术栈适用场景对照

| 引擎 / 栈 | 语言 / 特点 | 群内实测经验 | 适配平台 |
|---|---|---|---|
| **Web / H5** | HTML5 + WebGL / Canvas | AI 编程友好，开发效率快但画面/动态表现弱（`[2026-03-03] 李剑`）；前端库可用 **PixiJS**（`[2025-11-12 17:57] 韦舒松`「用pixijs试试水」） | 浏览器、Vercel、互动空间 |
| **Godot** | GD 脚本（文本）为主 | `[2025-09-25 16:57] AI发明家`：「目前 AI 编程对 godot 的支持应该是最好的，都是文本数据」；抖音小游戏**支持 Godot 但不支持 C#** | Web 导出、抖音小游戏 |
| **Unity** | C# | 生态成熟、有资源商店；但"版本升级全是坑，能不动就不要动"（`[2025-09-25 16:53] FYF`） | 移动端、抖音小游戏、Steam |
| **团结引擎** | = Unity 中国版 | `[2025-10-31 06:02~06:08] 李佳宁`：个人主体编辑器和导出**全部免费** | 抖音小游戏 |
| **Cocos Creator** | TypeScript | 国内引擎，对小程序/鸿蒙做了支持；默认 UI 案例不错；"之前 claude3.7 的时候我用过，生成的代码感觉不是很理想就改成 godot 了"（`[2025-09-15 22:33] AI发明家`）；**可一键打包抖音/微信小程序** | 微信/抖音小程序、鸿蒙 |
| **uniapp / 微信原生** | 前端栈 | `[2025-09-20 08:31] 赵子博`：uniapp 支持多端编译；流程是"画原型 → 让 AI 生成前端代码 → 再前后端对接" | 微信小程序、多端 |
| **Laya** | TS | "没啥人用 laya 的"，"用的人很少，有问题你得自己修"（`[2025-11-03 09:16~09:17] FYF`） | — |

李佳宁作为抖音小游戏官方，明确表态平台侧已支持的引擎矩阵：

> `[2025-11-03 17:17] 李佳宁`：「我们 laya/cocos/unity/团结/Godot 都支持嘿嘿」。
> `[2025-09-25 16:53-16:54] 李佳宁`：透露抖音这边「Godot 也在接，晚点儿跟大家见面」。

### 2.2.2 引擎与 AI 的协作方式：走编辑器 API，别碰工程文件

这是本部分**最重要的一条技术纪律**：

- **AI 不能直接改工程文件**：`[2025-11-03 17:09] FYF`——「你直接操作 cocos 的文件会崩的」。
- **正确做法是走编辑器扩展 API**：`[2025-11-03 09:00~09:01] FYF`——区分"game 场景和 editor 场景"，「你可以在 editor 场景下用代码生成，保存成文件，然后在游戏里就可以直接用了」「editor 是支持 api 方式操作的」。
- **目前没有成熟的游戏引擎 MCP**：`[2025-11-03 17:11] FYF`——「你如果需要游戏引擎的 mcp 的话，目前没有，但是你可以通过代码调用 editor 的 api 来实现所有功能」。
- **AI"认识但造不出"节点**：陈莫指出，模型能读懂 Cocos 序列化结构（`cc.SceneAsset / cc.Node / cc.UITransform / cc.Sprite / cc.Animation / cc.Camera / cc.Widget / cc.PrefabInfo` 等），但"不能直接创建预制体""也不能直接创建场景"，本质"还是在依赖脚本"（`[2025-11-03 08:55~08:57]` 陈莫）。Cocos 编辑器扩展文档：`https://docs.cocos.com/creator/3.8/manual/zh/editor/extension/extension-manager.html`。

**用 AI 开发引擎项目的标准姿势**（AI发明家总结）：

> `[2026-03-01] AI发明家`：「不用复制，直接用 TRAE 打开工程目录就行，生成的直接能用」「你先把 godot 项目创建好，再让 AI 改」，「引擎文档也要稍微看看，了解一些基本的概念」。

**另一个已验证组合**：`[2026-06-13 13:21-13:23] 吴晓斌`——「codex + godot 能不能自动做游戏？」「能，而且很适配」「Codex 的插件立大功」，有会员的话"甚至素材都可以他一手包办"。

### 2.2.3 引擎选择的现实困境

- **Unity 项目上的工具性能坑**：`[2025-11-19 07:40] vastchen`——"kiro 不知道为什么 CPU 奇高""我打开的是 unity 项目"，忽略 lib 目录也不行。
- **Unity 版本升级**："能不动就不要动"（`[2025-09-25 16:53] FYF`）。
- **资源文件不可见**：`[2026-01-05] 丁知成`——资源管理器文件列表中无法显示 Unity 的资源文件。
- **"游戏引擎支持 AI 之前，建议直接用 web"**：`[2026-04-09] 李巍`。

## 2.3 游戏架构设计：客户端/服务端权威与防作弊

### 2.3.1 核心原则：**让客户端发送操作，而不是数据**

这是 FYF 在本群里给出的一句话级防作弊铁律：

> `[2025-11-04 17:51] FYF`：「尽量让客户端发送操作，而不是数据」。

配套的几条可直接落地的判断：

- **计算必须放服务端**：`[2025-11-04 17:39] FYF`——「你这种游戏计算都应该在服务端，客户端只负责根据服务端数据渲染」。
- **相信客户端的都是类单机**：`[2025-11-04 17:41] FYF`——「相信客户端的一般那都是类单机的游戏」。
- **弱联网 ≠ 弱交互**：`[2025-11-04 17:46] FYF`——「弱联网不代表弱交互，只要你有玩家间的数据交互，最好就放服务端」。
- **不确定就全放服务端**：`[2025-11-04 17:47] FYF`——「不确定你就全放服务端，然后再往客户端移」。

### 2.3.2 反面案例：前端作弊真实发生过

群里有一条有名有姓的作弊案例，说明"减少前端"不是空话：

- `[2025-11-05 01:52] 用户031695`：「我朋友在崩坏星环都前端作弊，给自己加入了 1000000 游戏币」，而且"检测不到"；结论是"游戏尽量减少前端"。
- AI发明家点出根因：`[2025-11-04 17:40]`「相信前端就可以改包作弊了」；`[09:50]`「比如后端没有验证，会出现玩家通过改包，导致消耗 1 个道具抽几百次卡的 bug」。
- 周期性资产曲线审查也是一种兜底手段（`[2025-11-05 08:50] FYF`「这个都有的」）。

### 2.3.3 数值与存档

- **数值平衡参考 DnD**：`[2025-10-14 17:13] FYF`——「技能数值这块可以参考 DnD（桌游的平衡性还是在线的）」。
- **存档/弱联网**：FYF 对类率土之滨的判断——`[2025-11-04 17:06]`「简单来说，是的（近单机）。不过实际上会更复杂一些，你需要考虑防作弊/用户数据分析的话，还是需要发送数据到服务端的」。
- **游戏后端可选 Supabase**：`[2026-05-23 13:33] 吴晓斌`对"给我的游戏加上后端"的回应是「supabase 永远的神」。

### 2.3.4 抽卡/开箱动画的落地链路

抽卡、开箱这类"看起来很难"的效果，群里给出了两条可上手的路线：

- **传统链路（AE + Unity）**：`[2025-11-03 18:11] Morgan`——「二次元抽奖 抽卡 大部分都是 ae 做 然后到 unity 去设置触发逻辑就行」；命理召唤类特效"用 ae 做下就行"。
- **"动画做的真就真"**：`[2025-11-03 18:09] 陈莫`——「摇的时候播动画，出结果的时候动画消失或者隐藏，展示图片不行吗」「动画做的真就真」（即用动画替代真实物理模拟）。
- **不会 AE 的"轮椅路线"**：`[2025-11-04 00:14] 曹翔`——用 **spline** 工具，开箱动画先用 three.js 做，再导入工具默认动画，适合不会 AE、没搞过 Unity 的场景。

### 2.3.5 游戏服务端 vs 后台系统（概念澄清）

这是新手最容易混淆的一对概念，陈莫给过清晰定义：

> `[2025-11-03 17:20] 陈莫`：「服务端和后台不是一个东西」。
> `[2025-11-03 17:38] 陈莫`：「游戏服务端主要负责处理游戏逻辑，和条件验证，比如角色战斗过程或者什么条件满不满足，关卡能不能进，一般是用 socke 和前端通信的；后台负责活动配置，玩家行为分析，收入统计，游戏数据监控，账号管理，封禁处理之类的……」

要点补充：
- `[2025-11-03 17:20] AI发明家`：「后台主要是用来看游戏数据和运营的，不涉及游戏内容的修改」；后台核心指标是"留存、LTV、流水"（`[09:12]`）。
- `[2025-11-03 17:44] 陈莫`：新增角色/BOSS/关卡/装备是"策划配表后端和前端写功能实现的"；"玩法那些都是游戏服务端"。
- `[2025-11-03 17:33] 金杰`：可当作"同数据库 不同的后台调用"。
- 作弊/GM 工具"俗称 GM 工具，是一个作弊程序"（`[2025-11-03 17:48] AI发明家`）。

### 2.3.6 保底抽奖的运营设计

关于抽奖的"伪随机"本质，FYF 说得很透：

> `[2025-11-05 08:58] FYF`：「你花到了足够的钱，必中。然后要做的就是如何更像随机中的」。

并且提醒，"有时漏洞是运营手段"——郑铠聪举例小学玩天天酷跑"每天六点抽奖几乎 99% 概率出角色坐骑"（`[2025-11-05 08:55]`），FYF 判断"如果一直不修，一定有原因。多半对运营数据有很大帮助"（`[00:59]`）。

## 2.4 开发流程与工程纪律：需求 → 拆任务 → 实现 → 验收

### 2.4.1 让 AI 先定"规范/标准/流程/验收标准"

不要一上来就让 AI 写代码，先做对齐。群里的通用做法：

- `[2025-12-06] 用户031695`：「我建议你在开始项目之前先和 AI 聊天，确认你要干什么」。
- `[2025-12-10] 刘金良`：「你必须跟他沟通，让他指定规范，标准，流程，验收标准」。
- "先让 AI 定规范"之后，做游戏难点在于"AI 不知道动态的过程，调试也很难"。

### 2.4.2 四段式落地流程（以赵子博塔防为例）

赵子博用 TRAE SOLO 独立开发六边形塔防的真实流程，是一份可直接照抄的模板（`[2025-09-12 19:24]`）：

1. 从经典塔防入手（规则清晰）→ 搜集音效资源；
2. 下指令让 AI 出 PRD → 将策划案交 AI 生成代码；
3. 迭代优化 UI → AI 做数据配置 → AI 生成 SVG 图标（如"手持篮球、舞姿妖娆的僵尸"）；
4. SOLO 一键部署（与 Vercel 无缝集成）。

其首条指令原文：
> `[2025-09-12 19:24] 赵子博`：「你好，TRAE！请帮我开发一款以守卫基地为核心玩法的六边形塔防游戏。」

数据配置交给 AI 的方法：
> `[2025-09-12 19:24] 赵子博`：「我只需明确核心需求、字段和数值范围，AI 便能高效地完成数据配置，并能根据我的要求进行动态调整」。

### 2.4.3 Git 备份纪律（本手册最重要的工程红线）

群里围绕"AI 删库"有一条血的共识——**用 AI 开发，每完成一个任务就提交 Git**：

> `[2026-09-15 11:37] 张新`：「我用 ai 工具开发，都是让他完成一个任务就提交 git 的。用 AI 工具开发，还不用 git 管理，这能让人说啥呢？就算不用 AI，我也不敢让代码长时间放在本地，我会担心被自己不小心删除了。何况是 AI 呢。」
> `[2026-09-15 11:43] 张新`：「进入 git 后，就永垂不朽了，删除了再提交，也可以找回前一个版本的」。
> `[2026-09-15 11:25] jun`：「我是本地和远程都有 git」。

**真实"AI 删库"事故（必须引以为戒）**：

| 事故 | 经过 | 出处 |
|---|---|---|
| MiniMax 删库 | 「我就说了一句把垃圾清理干净，他把我整个数据库连同 git 一起删的干干净净」，且 AI 还总结"都清理干净了" | `[2026-09-15 11:49-11:51] 吴晓斌` |
| D 盘被清空 | 「有一次好像是开着 Trae，2025 年底，Gemini 3 pro。然后我 D 盘突然清空了」「harness 有问题」 | `[2026-09-15 11:22] 用户031695` |
| Kimi 提交旧文件 | 「commit 给我提交成旧文件了，差点把我一天干的活覆盖了，从此以后就不敢让 kimi 碰后端了」 | `[2026-07-19 16:12] 用户490066` |
| 强制钩子也拦不住 | 「在我设置强制钩子的情况下删的，就问你绝不绝」 | `[2026-07-19 16:15] 吴晓斌` |

### 2.4.4 写规则 / 文档让 AI 少犯错

- **规则用 md 承载，拖给智能体**：`[2025-11-18 10:40] FYF`——「整理一个 md 规则，要得时候后拖到整理代码的智能体上，会一并处理的」。
- **Few-shot 示例显著提升准确率**：`[2025-11-18 12:17] 冬沐`——「提示词中贴示例确实很好用……贴上示例后，准确率提升了很多」。
- **旧模块改造策略**：`[2025-11-19 07:36] vastchen`——「目前我只敢让 AI 写单独的模块，旧模块都是先分析给方案在一步步执行」。
- **"避坑手册"记忆迁移法**：`[2026-06-10 11:34] AAG`——「我的办法是写避坑手册，抽象通用方法，只展示技术坑……迁移的时候会让他再扫一遍」；并写了规则"每次对话结束自动整理"。
- **规则放哪最有效**：`[2026-07-29 19:38-20:07] AAG / Zen`——AAG 认为"放 system prompt 能好一点"，并提醒 trae 的规则与自身 sys prompt"会打架"，"不如每个迭代对话重复一下要遵守的规则"；Zen 说 solo 设置里有填规则处，但"照样不遵循"，"直接输入提示词才遵守"。
- **框架必须先优化好**：`[2026-04-10] 用户276564`——「前面框架不优化好，后面 bug 多了 ai 根本解决不了问题」「框架文件要区分好才行，功能都写一起后面绝对完蛋」。

### 2.4.5 素材与美术的"工程化"做法

- **素材占位法**（避免 AI 设计得丑）：`[2026-03-13] 飞书用户6716MT`——「提示词可以在 Trae 做，让他给你留占位」「把需要的素材都输出，素材名称、提示词」「你生成好按照指定位置放进去」。
- **先跑 demo 再完善**：`[2025-12-04] 刘金良`「现有了 demo，然后用 trae 完善」；郑铠聪的圣诞游戏亦"全程用 TRAE 跑个 demo，然后后面再优化细节"。
- **素材处理流程**：`[2026-02-02] 李巍`——「先找接近的素材，让 AI 抠图，再让 AI 按你的想法改」。
- **序列帧/精灵图集的完整科普**（`[2026-04-08] 耿家威`）：设计关键帧 → 补齐中间帧（动画十二法则）→ 拼成图集（省钱减少 Draw Calls）→ 进引擎切片（如每秒 12 帧）；生产工具：Aseprite、Krita、PS/Procreate、TexturePacker；骨骼动画（Spine）vs 逐帧动画（如《空洞骑士》《茶杯头》）。
- **Spine 动画的现实结论**：AI 做不了——"人物结构都是散的""spine 动画还是得要专业动效来做"，故"目前放弃 spine 动画，改用帧动画，等 ai 能力到了再用 spine"（`[2026-08-17 02:26~02:28] AI发明家 / 李巍`）。

## 2.6 上线与部署：Godot 导出 Web、Vercel、IGA Pages 的实践与坑

### 2.6.1 从 Godot 到 Vercel 的链路

最短发布链路：**把 Godot 游戏导出成 web，然后用 TRAE 部署到 Vercel**（`[2026-04-21 12:48] AI发明家`）。赵子博的塔防 DEMO、郑铠聪的圣诞游戏也都是用 SOLO/TRAE 一键部署到 Vercel 的（示例：`https://traerhi87dhl.vercel.app/`）。

### 2.6.2 Vercel 的坑

- **屏蔽中国大陆网络**：`[2026-04-29 18:00] JasonShane`——`*.vercel.app 屏蔽中国大陆网络`。
- **大文件卡顿**：`[2026-04-29 17:58] AI发明家`——"vercel 超过 20M 的文件会卡住"。
- **国内版当时无法一键部署**：`[2026-04-29 17:57] 用户039583`——互动空间"说白了其实是 vercel 代餐"，国际版 TRAE 能一键部署 vercel，国内版当时还没有。

### 2.6.3 静态部署平台横向对比

| 平台 | 容量 / 限制 | 说明 | 出处 |
|---|---|---|---|
| **Vercel** | >20M 卡住；屏蔽大陆 IP | 国际版可一键部署 | `[2026-04-29]` AI发明家 / JasonShane |
| **火山 IGA Pages** | 可放 1G | 部署 zip 包，"本质其实就是能部署一个网站的地方"，可用官方 skill 部署；"感觉就是互动空间的放大版" | `[2026-04-29 09:49~10:21]` AI发明家 |
| **腾讯 EdgeOne** | 25M 限制 | "腾讯 EdgeOne 也一样" | `[2026-04-29 18:28]` JasonShane / AI发明家 |
| **阿里 ESA** | — | 同类静态部署平台 | `[2026-04-29 18:28]` JasonShane |
| **4399** | 可放 2G | — | `[2026-04-29 17:50]` 用户039583 |
| **抖音互动空间** | ZIP 8M 以内 | 产物为 HTML 代码包、纯静态 | `[2026-04-16 11:32~11:34]` 李佳宁 |

火山 vs Vercel 的实测体感：`[2026-04-29 18:31] AI发明家`——「火山这个我感觉差不多的，资源可能还比 vercel 多一点，加载更快」。

### 2.6.4 部署踩坑三则

1. **火山"预览"是限时三小时的**：`[2026-04-29 20:07] 用户039583`：「预览是限时三小时的呀，我以为像 github pages 一样可以一直用」；AI发明家澄清"可以一直用啊""预览和他给的不是一个网站"。
2. **自定义域名 DNS 验证失败**：把项目设置里的域名当自定义域名会被判"验证 dns 失败"，因为它不是你的自有域名。解法是"能不能部署用平台自有域名；自定义域名需自购并做 DNS 验证"（`[2026-04-29 20:10] AI发明家 / JasonShane`：「618 买一下就行了」「我的 188 块 10 年」）。
3. **互动空间的离线硬约束**：完全离线运行、禁止任何网络请求 API（fetch/XMLHttpRequest/WebSocket）、禁止外部 CDN、体积 <8MB（`[2026-04-17 16:48] 耿家威`）。FYF 就踩过体积的坑——"我加了声音，就 3m 去掉了"（`[2026-04-20 15:43]`），为控体积删掉了音效。

### 2.6.5 客户端打包到手机

- `[2026-03-01] 李巍 / 李剑`：做成网页版，局域网直接浏览器输入本地地址即可玩；上传 Vercel 可让手机访问；安卓也可用 UU 模拟器。
- `[2026-03-04] 李巍`：可以用 **Capacitor** 把 web 应用打包到手机端。

## 附：AI 辅助游戏开发速查清单

**选题**：规则清晰、玩数值、挂机放置、H5 轻量 → 优先；美术/动态表现重 → 谨慎；注意"游戏=成长或数值体系"的平台口径。

**引擎**：Godot（AI 文本友好、抖音支持但不支持 C#）、Cocos（一键打包小程序/鸿蒙）、Unity/团结（生态成熟、版本别乱升）、Web/H5（最快出 demo）。

**与 AI 协作**：走编辑器 API，**绝不直接改工程文件**；先把项目建好再让 AI 改；无引擎 MCP 时用编辑器 API 兜底。

**架构**：客户端只发操作不发数据；计算放服务端；弱联网也要服务端交互；数值参考 DnD；抽卡动画 AE/spline 皆可。

**纪律**：需求对齐 → 拆任务 → 实现 → 验收；**每完成一个任务就提交 Git**（本地 + 远程双备份）；写 md 规则/避坑手册。

**测试**：让 AI 生成测试日志自优化；浏览器测试只信视觉理解型；关键节点真人试玩；让 AI 出人工测试点。

**部署**：Godot 导出 web → Vercel（国际版，注意大陆屏蔽）；火山 IGA Pages（1G）；EdgeOne（25M）；互动空间（8M 纯离线）；注意自定义域名要 DNS 验证。
