> **收录口径与使用说明**
> - 全部信息来自群友在群里的口头自述，**未必全面**（很多人只提了一句、未细说技术细节），也**未逐一核实**。
> - 作者一律按群昵称记录；技术栈、状态严格依原文，凡原文未说明之处统一标注「（素材未说明）」，**不作推测**。
> - 表格按时间先后排列；时间/来源列给出群聊时间，无明确时间的标注所在素材分片。

## D.2 代表作品复盘

### 1. 赵子博：六边形塔防游戏（纯 SOLO 独立开发）
2025 年 7 月末拿到 SOLO CODE 体验资格后，赵子博用 TRAE SOLO 从零做出一款六边形塔防。做法有一套清晰的流水线：选规则清晰的经典塔防切入 → 搜集音效资源 → 下指令让 AI 出 PRD → 把策划案交给 AI 生成代码 → 迭代优化 UI → AI 做数据配置 → AI 生成 SVG 图标（甚至做出「手持篮球、舞姿妖娆的僵尸」）→ 最后用 SOLO 与 Vercel 无缝集成一键部署。结果是完成了一个玩家可布置单位、收集资源抵御僵尸的功能完整 DEMO。可借鉴之处：把「策划案」当作 AI 的输入起点，让 AI 承担策划、程序、UI、数据、美术、部署多个环节，验证了 SOLO「一个人跑通全流程」的能力边界。

### 2. 用户815023：《挂机鉴仙》（已上架 TapTap 的挂机修仙）
这是一款用 Trae 做的文字放置挂机小游戏，玩法含抽卡、鉴定卡牌随机机制。它已上架 TapTap，作者一度晒出「1200 下载」，并拿到了电子版权证书，计划后续接入广告变现。作者的经验很实在：纯单机游戏「不需要域名，上架平台也不需要资质」，TapTap 还可以测试方式上架；他自评「这个练练手」。这条作品在素材中信息最完整——从技术工具、玩法、上架平台、下载量、版权进度到资质门槛、变现路径都有交代，是理解个人开发者用 AI 做小游戏完整闭环的一个典型样本。

### 3. 陈彰：《千面三国》（业余时间上架的小游戏）
「用 trae 做的小游戏上架了」，被群友称为「三国版羊了个羊」。它做了「小半年吧，下班时间边学边做」，群友评价「点进去完全看不出是 trae 做的，完成度好高」。作者自己也很清醒：「后期会比较难，关卡数上去后」，随后迭代上线了图鉴。可借鉴的点在于：一是业余碎片时间也能把一款游戏真正推到上架；二是关卡类小游戏的难度曲线会随关卡数增长而变陡，需要提前设计内容与数值的可持续产出方式。

### 4. AI发明家：FateShaper（Godot 卡牌游戏）
技术栈是 Godot，运镜视频用 seedance 做，整包资源约 500M。作者自述「我游戏有首通玩家了」，说明已跑通完整可通关流程。但群友试玩反馈了大量问题：部分按钮变形、卡牌有重复牌面（作者解释是不同的「基础牌」）、存在「桌面不结算/空回合」疑点（作者解释是第一波怪打太快）。作者的态度值得学习——主动求群友截图指出「看着不太舒服的地方」，并总结「通不了关太折磨玩家了」。教训：卡牌游戏的 UI 细节、牌面可辨识度与难度平衡，是 AI 生成之后仍需人工反复打磨的部分。

### 5. 用户490066：Rurix / RurixForge（自研 AI 原生引擎与渲染器）
用户490066 基于 rust 先设计了一个 GPU 语言，再让 AI 搭出一个渲染器，目标是做「AI 原生」的游戏引擎；引擎层还在做，渲染器已开源发布 RurixForge。过程并不顺利：「抗锯齿灯光啥的还是不行，继续修」「今天也是燃尽了，明天再修」，4K 图仍有点糊。他给自己做了清晰定位——「我只确保流程能用，真正商业化不是一个人能干成的事」。可借鉴的是「不等现成方案、自造轮子」的探索路径，以及小渲染器还能顺手「搓个小游戏」验证；但也提示个人做商业级引擎的现实边界。

### 6. 用户031695：spinshare.dev（把「做出来」和「被看到」分开看）
这是一个想借 Claude Code 庞大用户基数做「加载等待时付费广告、给开发者分红 60%」的网站/插件，用 Claude Code + Codex/Opus 开发，接入 Firebase、Google/GitHub 登录与 Stripe。速度惊人——「6 天我写了几乎 6 万行代码」，后达约 30 万行。但结果给了一记清醒的教训：迟迟「没地方 distribute」，「一样的项目，那个人 9000 万个广告了，我 9 个广告」，最终得出「distribution is everything」、还发现自己「整个广告用户群体都选错了」。这条复盘的真正价值不在代码，而在于印证了素材中反复出现的判断——AI 时代做出来不难，分发与触达用户才是瓶颈。

### 7. 吴晓斌：Vampire-Hunter-Roguelite（Godot 吸血鬼幸存者）
用 Godot 做的一款类吸血鬼幸存者 Roguelite 游戏，素材全用 Kimi 生成，已开源在 GitHub。作者自评颇狠：「贼无聊，2 分钟无敌」「我玩了 5 分钟就不玩了」，并把项目定格为「美术简直惨不忍睹，但是 demo 的形状肯定是有的」。他由此得出一条被群内反复引用的结论——「发现美工才是最后一道鸿沟」「美工还是要自己操刀的」。可借鉴点：AI 能快速把玩法框架（demo 形状）搭出来，但决定游戏能否成立的品质感、美术与耐玩度，仍要人自己下功夫。

### 8. 李佩恒：微信小程序 number-bomb-public（15 天 2w 用户）
用 TRAE 做的一款微信小程序，上线 15 天即达到 2w 用户，随后反馈到 3w 用户，作者把项目开源（number-bomb-public）。它的价值在于验证了一套可复用的冷启动打法：在 UP 主视频评论区留言求大家玩、「这种也算推广的一部分」，并设计促活引导分享，「玩的人多了自发推荐的就多了」。可借鉴之处：小程序类轻量产品，把「运营与分发设计」前置到产品里，往往比继续加功能更能带来增长。

## D.3 小结

- **作品谱系**：群友作品以**小游戏**为主（塔防、卡牌、Roguelite、挂机放置、足球、RPG、文字对战等），其次是**工具与引擎**（SOLO 插件、自研引擎/渲染器、harness、各种 Skill）、**AIGC 作品**（视频、音乐、封面、3D 模型、素材、表情包）与**小程序/网站/系统**。
- **高频工具**：TRAE / TRAE SOLO 是贯穿始终的主力；游戏侧常见 Godot、Cocos、WebGL/three.js；AIGC 侧常见豆包、Kimi、MiniMax、seedance、妙响等。
- **反复出现的教训**：① AI 能快速出 demo，但「美工/艺术仍是最后一道鸿沟」；② 做出来不难，**分发与运营**才是变现难点（distribution > product）；③ 小项目顺畅、大项目（微服务/长链路）易成「屎山」；④ 上架合规（软著、版号、平台规则）是绕不开的现实门槛。
